# Electrical and gravity field candidates

These original candidates have been imported to four separate assets, fresh-validated in Unreal 5.8.2 and rendered in eight unsaved native views. They are not selected by gameplay or owner-approved art. No bitmaps, downloads, external assets or host installations are used.

| Candidate | Geometry | Source triangles | Sections |
| --- | --- | ---: | ---: |
| SM_ElectricalFieldCandidate | Eight branching main bolts with sixteen offshoots and three thin outer filaments | 3,168 | 1 |
| SM_GravityFieldCandidate | Nine curved streamlines moving from outer to inner radius and three thin outer filaments | 3,588 | 1 |

Both use closed, four-sided thin tubes with open space between them. The Unreal materials are opaque/unlit and single-sided: no transparent volume shell, opacity animation, WPO, refraction, authored texture lookups or extra light actors. The geometric gaps preserve the interior view; distant line readability and screen coverage across gameplay views still need validation. The three continuous low-level outer filaments suggest the spherical extent without claiming a filled volume boundary.

OBJ coordinates are centimetres, +X forward and +Z up. Each candidate is centred at zero, has exact +/-100 cm bounds on all axes, and contains no vertex beyond radius 100 cm. This preserves the existing radius divided by maximum mesh-extent normalization if later adopted. The Blender inspection files use metres with the same axes and a simple static emission material; they are not faithful previews of the Unreal procedural shader.

## Material and timing contract

UV0.x packs `role*4 + longitudinal_fraction`: boundary=0, primary=1, branch=2. UV0.y packs `strand_index*2 + circumference_fraction`. Coordinates are deliberately outside the 0-1 range and require one retained UV channel. Every triangle has one role.

Both dedicated shaders accept exact `Tint`, `Color` and `Emission` parameters plus UV0 and material Time. Runtime-compatible defaults are Color=(1,1,1), Emission=0.25, electrical Tint=(0.24,0.55,1), gravity Tint=(0.6,0.18,1). The boundary branch has a fixed positive brightness floor and no Time input dependency. Internal Time variation is slow, bounded detail; it is not a pulse or activation clock.

Electrical intensity follows the current `AdvanceElectricalPulse` Emission value, including its charge ramp, 2.8 discharge and existing decay. No shader threshold changes damage, telegraph duration, radius or pulse interval. Gravity amplitude follows the existing Age/TelegraphSeconds-driven Emission; decorative flow travels toward increasing U, from outer to inner points. It does not start or change force application. There is no independent material flash schedule.

The current runtime overrides field slot 0 with shared M_Emissive. These candidates require a later reviewed field-only material selection before adoption. Import alone will not change gameplay. Keep SM_GravityRing intact because the Wave 5 wormhole also uses it. Keep M_Emissive intact because enemies, projectiles, pickups, events and depots share it.

## Files and workflow

- Generate.py creates only the two OBJ/blend candidates, local MTL and SourceReport.json. It runs in an isolated Blender background process without rendering.
- ElectricalField.hlsl and GravityField.hlsl contain the field-only procedural material bodies.
- SourceReport.json binds generated bytes, shader sources, exact geometry measurements and eight protected original/runtime inputs. Analytic projected triangle-area sums are conservative geometry statistics, not rendered visibility or performance measurements.
- CheckSource.py independently parses the actual OBJ files and verifies counts, spherical bounds, finite/nondegenerate triangles, normals, UV role isolation and provenance.
- ../../Scripts/AuthorFieldCandidates.py is the separate Unreal import script. Its writes are restricted to these four new paths: `/Game/SpaceSurvival/Meshes/SM_ElectricalFieldCandidate`, `/Game/SpaceSurvival/Meshes/SM_GravityFieldCandidate`, `/Game/SpaceSurvival/Materials/M_ElectricalFieldCandidate` and `/Game/SpaceSurvival/Materials/M_GravityFieldCandidate`. It refuses unknown existing assets and never selects Data Asset entries.
- ../../Scripts/ValidateFieldCandidates.py is the fresh-editor read-only validation script; it checks geometry/UV/material/parameter/collision contracts and writes a validation receipt.

Generation command, from the repository root:

```powershell
& 'C:/Program Files/Blender Foundation/Blender 5.1/blender.exe' --background --factory-startup --threads 4 --python ContentSource/FieldCandidates/Generate.py
python ContentSource/FieldCandidates/CheckSource.py
```

Lead source review approved exactly four new isolated assets. Import, fresh validation and native preview ran sequentially after the enemy preview window closed. `Scripts/PreviewFieldCandidates.py` uses an unsaved scene with the actual ship/asteroids/sky and holds existing numerical Emission values for warning/charge/discharge and gravity edge/interior inspection. It does not execute a gameplay pulse clock, GameMode, HUD or player input.

Those are visual limitations of this candidate, not acceptance. The interior view deliberately places a static ship reference near the camera; no pilot, flight fairness, temporal aliasing, live damage/force clock, audio, packaged performance or owner art approval was tested.
