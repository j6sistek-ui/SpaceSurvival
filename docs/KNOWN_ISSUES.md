# Known issues and limitations

**Phase 1: PARTIAL.** Updated 2026-09-13 UTC. The Windows package builds, 12 Unreal tests pass without test warnings/failures, and isolated fresh-process storage passes. These results do not close the remaining player-experience requirements.

## Open implementation and quality gaps

1. **The owner rejected the graphics as far below acceptable.** Generated spacecraft, station and secondary meshes/materials are provisional, not selected final art. A substantial art replacement pass is required. Preserve the supplied Acornaut. The space treatment, HUD, VFX and synthesized audio also need integrated art/mix review.
2. **Character presentation remains provisional.** The corrected-tail pilot mesh and seated animation are imported, fitted in previews and wired into the ship; the original walking asset is preserved. Continuous flight/camera clearance, foot contact and the 1.4-second procedural disembark still need hands-on review. The procedural transition is not a finished authored exit animation.
3. **Station presentation remains rudimentary.** Native consoles, service machinery, a primitive moving Mica avatar, ambience and a story/reward beacon exist. There is no finished skeletal vendor or recorded dialogue. Acornaut reactions are cooldown-limited subtitle captions.
4. **Station 2 boundary is unresolved.** It supports services/suspension but disables further launch. Labelled abandonment discards the run without death XP/history. This is not an owner-approved resolution of indefinite survival versus the ten-wave slice, and it does not establish completion/restart appeal.
5. **Input needs physical-device acceptance.** Adapter tests cover movement at 30/60/120/144 Hz, boost/brake, directional dodge collision and manually triggered weapons. They call gameplay methods directly. Keyboard/mouse feel, controller parity, hold/toggle, live-menu focus, reconnects and comfortable camera behavior remain unverified.
6. **Natural balance and Director fairness are unproven.** Required Wave 10 admission and event route checks now have deterministic regression coverage. The accelerated journey uses 12-second waves, enlarged durability and forced/assisted objectives. It does not establish purchase cadence, natural event routes, reaction windows or compound-climax readability.
7. **Storage has remaining failure and UI gates.** Actual GameInstance persistence across fresh processes passes, including suspension consumption, resumed death, settings, XP/unlocks and fresh-run reset. Real locked-suspension/account replacement failures now preserve prior bytes and allow successful retries with once-only XP. Real station Save & Quit/Continue interaction, packaged lifecycle, corrupt-account recovery, forced interruption, disk-full/short writes and staged-readback failure remain unverified. The staged writer supports only the verified generic local Windows backend. There is no atomic transaction across slots or automatic backup manager.
8. **UI/audio need rendered and listening checks.** Unlock milestones, complete contract terms, non-color threat direction and spatial Alarm playback exist. Alarm has a six-second cooldown; reactions have an 18-second cooldown. Mix, urgency, subtitle/menu layout, maximum UI scale and small-screen usability have not passed acceptance. A native click changed mouse sensitivity from 1.0 to 1.2; package 5 relaunch at 1280x720 displayed mouse 1.2/controller 1.0. Preference persistence passes this smoke; comfort and physical-input behavior remain open.
9. **Some tunable content remains native.** Fixed hazard/enemy/pickup/encounter catalogs are editable, but weapon/utility/contract policies, reward offerings, station layout and menus still require C++ changes. Native factories and synchronous loading limit designer extension.
10. **Performance acceptance and broader packaged coverage remain open.** Package 5 builds and renders New Run; package 4 separately verifies startup scalability and supplies the measured performance identity. Earlier package 3 smoke exercised neutral-controls death/results/restart and retained the account after relaunch. Package 4's neutral-controls Waves 1–3 sample measured about 119.96 FPS at a 120 FPS cap, p99 9.119 ms, maximum 10.898 ms and zero active-flight frames above 16.667 ms. The separate startup frame reached 2,174.921 ms; its cause requires a trace. Both climaxes, stations and full-run process memory remain unmeasured. See [PERFORMANCE.md](PERFORMANCE.md). These results do not establish active piloting, a complete ten-wave run, offline/failure coverage, the 60 FPS baseline or higher-refresh scalability.
